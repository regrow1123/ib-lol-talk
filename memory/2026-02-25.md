# 2026-02-25

## Major Architecture Change: State Machine (plan/resolve)
- Refactored from 1 LLM call per turn to 2-call architecture:
  - `/api/plan` — generates player 3 actions + enemy 1 action
  - `/api/resolve` — judges results (hit/miss, narrative, aiChat)
  - Old `/api/turn` renamed to `/api/resolve`
- Enemy action pre-determined in plan phase, player picks from 3 or types free text
- Sub-agent did the bulk implementation (8 files, ~840 additions)

## Prompt Simplification
- Massive reduction 234→123 lines. Removed all LoL knowledge Claude already knows (skill descriptions, aggro rules, wave management, trade types)
- Kept only game-specific rules: elapsed tiers, JSON format, "no numbers" rule, CS table, skill notation
- Action context moved from system message to user message for better LLM comprehension
- Skill names (음파/공명타격) used instead of Q1/Q2 codes — LLM handles names better

## Enemy Auto Skill-Up
- Removed LLM `enemySkillUp` field entirely
- Hardcoded top lane Lee Sin skill order in `lee-sin.json` → `enemySkillOrder` field
- Server auto-applies on level-up, no LLM dependency
- Enemy learns first skill (Q) at game start

## UI Changes
- Typing indicator: animated dots bubble (enemy-style white bubble)
- Suggestions: vertical layout, left-aligned, shrink-to-fit
- Skillup buttons: horizontal row, same style as suggestion chips
- Unlearned skills shown as grayscale (opacity 0.3) in status bar
- Champion select UI on setup screen (extensible via `data/champions/index.json`)
- All images local (no DDragon CDN)
- Skill names with QWER keys appended in suggestion chips display: "음파(Q1)로 견제"
- Game over tips: LLM generates 3 match-specific tips

## Damage/Balance Fixes
- bonusAD→totalAD scaling (no items = bonusAD always 0)
- Turn order: time passes first (cooldowns/recovery/regen) → actions at end (energy drain visible)
- Suggestion text: player first-person casual voice

## Current Issues
- LLM response quality still lower than vanilla "let's 1v1" prompt — ongoing tuning
- Action context alignment between plan choices and resolve narrative needs testing

## File Structure
- `api/plan.js` (new), `api/resolve.js` (renamed from turn.js), `api/skillup.js`
- `server/prompt.js` — buildPlanPrompt + buildResolvePrompt (shared GAME_RULES const)
- `server/llm.js` — callResolve (resolve-only)
- `data/champions/index.json` (new) — champion list for select UI
- `data/champions/lee-sin.json` — added `enemySkillOrder` field
